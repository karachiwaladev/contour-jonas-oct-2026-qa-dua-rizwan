## A. Session started in the parent folder, not the repo

The session ran with `D:\Hackathon khi` as its project folder. Project skills,
hooks, `.claude/settings.json` and `.mcp.json` load only from the session's folder,
so the skill was missing, the guard was off, and Chrome opened on the shared profile.

- `Unknown skill: factory-loop` at 2026-10-26 06:43 (transcript), right after the
  skill was created; prompt log L13 "how to call it".
- Four `new_page` failures, "The browser is already running for ...chrome-profile",
  06:03 to 07:29 (transcript). Ticket #4 was blocked on it:
  [comment](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-dua-rizwan/issues/4#issuecomment-6410591227),
  whose own unblock advice was "Start Claude Code from the repo folder and approve
  the `chrome-isolated` server". The repo's `.mcp.json` defines that server; it
  never loaded.
- Ticket #4 first answer: "Not verified: I didn't click through the page in a real
  browser"
  ([comment](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-dua-rizwan/issues/4#issuecomment-6410241724));
  ticket #5: "I still couldn't click through it in a real browser"
  ([comment](https://github.com/karachiwaladev/contour-jonas-oct-2026-qa-dua-rizwan/issues/5#issuecomment-6410342287)).
- /insights friction: "a locked Chrome automation profile required user approval to
  kill the stray browser processes".

**E1 (applied, SKILL.md Setup step 0):** the session must start in the repo root;
if `git rev-parse --show-toplevel` is not the working directory, tell the user and stop.
**E2 (CLAUDE.md, one line under Rules):** "Start Claude Code in this folder, never
its parent: skills, hooks and the isolated browser load only from here."

## B. Slash commands typed into Git Bash become Windows paths

Git Bash rewrites a leading `/name` into `C:/Program Files/Git/name`.

- Prompt log L31 `/skill-doctor` (in Claude Code, fine) then L32
  `C:/Program Files/Git/skill-doctor`, typed from a shell.
- Both first nested runs today, `claude -p "/skill-doctor"` and
  `claude -p "/doctor prompt-audit ."`, received a file path and did other work
  instead. Reruns with `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'` worked.

**E3 (CLAUDE.md, one line under Rules):** "Type slash commands in the Claude Code
prompt. From Git Bash, prefix `MSYS_NO_PATHCONV=1`, or `/skill-doctor` becomes
`C:/Program Files/Git/skill-doctor`."
